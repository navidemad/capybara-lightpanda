# Ruby CDP Peer Gems

This file tracks design inspiration from peer Ruby CDP gems — separate from `lightpanda-io.md`, which documents the **browser** upstream. Findings here are about *how* we structure code, not about *what's possible* in the browser.

Maintained by the `sync-upstream` skill (Ferrum / Cuprite targets). Don't write a changelog — when a pattern is adopted in the gem, move it from "Outstanding" to "Adopted" inline.

---

## Ferrum

Repo: https://github.com/rubycdp/ferrum
Role: peer Ruby CDP client. Active, idiomatic; primary peer-gem reference.

**Last reviewed**: 2026-08-28 against Ferrum **v0.18.0** (released 2026-08-20, first since 0.17.2) and `main` HEAD `80a0560b` — unmoved since 2026-08-26, so no code has landed since `d3544251`; the open queue is still #617 alone. Verdicts settled, don't repeat:

- **Merged, gem already conforms or immune**: #602 thread-safe CDP send path (`client.rb#next_command_id` under `@mutex`, `client/web_socket.rb` guards `text`/`close`/`parse` with `@driver_mutex`); #603 logger-before-delivery ordering; #611 `select_file` via `backendNodeId` — a nodeId-instability bug we can't have, our nodes bind `objectId:` straight into `DOM.setFileInputFiles`; `abed1010` atomic `find_or_build_exchange` — their race is `requestWillBeSent` vs `Fetch.requestPaused` on two threads, we have no Fetch path and one dispatch thread behind `@traffic_mutex`; #573 `:pending_connection_errors` default → false — our `wait_for_idle` already returns `false` and only the bang form raises; #360 stale-node retry removed (their `runtime#call` burned 0.6s of sleeps retrying `NodeNotFoundError` on node-bound evals) — ours never had it: `Node#call` retries only `NoExecutionContextError` via `with_default_context_wait` (`wait: 0`, event-gated on `executionContextCreated`), `ObsoleteNode`/`NodeNotFoundError` propagate straight to Capybara's `automatic_reload`; cyclic-check-per-nested-object fix (~4k round trips per big evaluate) — we serialize with `returnByValue: true`, no client-side object walk exists; worker attach/detach `TimeoutError` escaping into the subscriber thread and killing it — our `Subscriber#dispatch` rescues per callback, and we attach no workers.
- **Merged, N/A**: #600 select-all via the CDP `commands` field (no `commands` support in Lightpanda's `Input.dispatchKeyEvent`; `Node#set` writes `.value`); #604 intercepted-request patterns (no Fetch); #598 webrick optional (no dependency); #595 `page.accessibility` and #613/0.18's Worker+ServiceWorker surface (raw-client surface with no Capybara counterpart — and Lightpanda already routes worker network events through the page session, #3037); #610 `--no-crashpad`, #539 `targetCreated` for pre-existing targets (Chrome target discovery); `wait_for_selector` [#82] (Capybara's own retry loop covers the driver surface; `LP.waitForSelector` exists browser-side if a raw API is ever wanted); `Page#on(:response)` on `loadingFinished` [#294] (no exchange/body surface; traffic hashes + `wait_for_idle` serve the Capybara use case); 0.18's `:protocol_timeout` split (our `Client#command` takes a per-call `timeout:` override over the single `options.timeout` — same effect, no second knob); `quit wait: false` background teardown (our at_exit teardown is synchronous by design, pinned <2s by `teardown_test`); process-group TERM→KILL group-polling + user-data-dir cleanup retries (Lightpanda is a single process with no user-data dir; our `Process#signal` already hits `-pid` with TERM → 3s grace → KILL); #552 `:host` substitution and `--remote-debugging-address` removal (Chrome spawn plumbing — we parse the address the server logs); #609 `IO.close` on PDF/tracing streams; #618 touch emulation on `set_viewport(mobile:)` (no mobile-emulation surface in the driver, and Lightpanda accepts-and-warns `mobile` on `setDeviceMetricsOverride`).
- **Merged, browser-blocked**: #605 console stack traces — Lightpanda emits no `stackTrace` on `consoleAPICalled` (same gap that put `page_errors` on the `errors.js` sentinel channel); the `type` half we already had (our upstream PR #2731).
- **Still open**: #617 "redesign the JavaScript evaluation API around named arguments" (opened 2026-08-23 — would reshape the `evaluate`/`evaluate_func` surface our Runtime module mirrors; re-grade on merge), #527 mobile emulation (stale).

### Adopted

- **`Node#exists?`** — `lib/ferrum/node.rb#exists?` (probes `DOM.resolveNode`) ↔ `lib/capybara/lightpanda/node.rb#exists?` (a no-op `call`, so the same `isConnected` guard answers; `ObsoleteNode`/`NodeNotFoundError`/`NoExecutionContextError` → false, anything else still raises).
- **`Utils::Event`** — `lib/ferrum/utils/event.rb` ↔ `lib/capybara/lightpanda/utils/event.rb`. Iteration-counting wrapper around `Concurrent::Event` so callers can detect a wait was raced by a reset. Our copy notes "Mirrors ferrum's Utils::Event".
- **`Cookies::Cookie` typed wrapper** — `lib/ferrum/cookies/cookie.rb` ↔ inner class in `lib/capybara/lightpanda/cookies.rb`. Typed accessors over the raw CDP hash (`name`, `value`, `domain`, `httponly?`, `secure?`, `same_site`, `expires` as Time). Our copy notes "Mirrors ferrum's Cookies::Cookie".
- **`Cookies#store` / `Cookies#load`** — Ferrum 0.16 (Dec 2024) ↔ our `lib/capybara/lightpanda/cookies.rb`. YAML round-trip of all current cookies. Same signatures (`store(path = "cookies.yml")`, `load(path = "cookies.yml") -> true`).
- **`Node#wait_for_stop_moving` shape** — `lib/ferrum/node.rb` ↔ `lib/capybara/lightpanda/node.rb`. Poll `getBoundingClientRect` until two consecutive samples agree. We deliberately deviate by NOT raising `NodeMovingError` — see "Diverged on purpose" below.
- **`Browser::Network#wait_for_idle` + traffic tracking** — `lib/ferrum/network.rb` ↔ `lib/capybara/lightpanda/network.rb` + `Driver#wait_for_network_idle`. Tracks in-flight HTTP via `Network.requestWillBeSent` / `responseReceived`; exposes `traffic`, `clear`, `wait_for_idle`, `headers=` / `add_headers` / `clear_headers`. Redirect hops close the previous entry from `redirectResponse` and responses resolve onto the last open entry for the id (Ferrum's `subscribe_request_will_be_sent` shape; Lightpanda re-emits `requestWillBeSent` per hop since #3175). We DON'T mirror `Network::Exchange` typed wrapper — traffic items are loose hashes. Sits alongside the bespoke Turbo activity tracker in `javascripts/turbo.js` (Turbo can settle while long-poll connections are still open).
- **BrowserContext-per-session reset** — `lib/ferrum/contexts.rb#reset` ↔ `lib/capybara/lightpanda/browser.rb#reset` + `driver.rb#reset!`. Each session owns a `BrowserContext`; reset disposes it via `Target.disposeBrowserContext` and creates a fresh one — wipes cookies/storage/targets in one CDP call. Sidesteps `lightpanda-io/browser#2363` since we don't navigate to `about:blank`. Reset also calls `Network#reset` (not `#clear`) so `@enabled` flips back to false (the disposed context's Network domain is gone, so the next `#enable` must re-subscribe).
- **`Utils::Attempt.with_retry(errors:, max:, wait:)`** — `lib/ferrum/utils/attempt.rb` ↔ `lib/capybara/lightpanda/utils/attempt.rb`. Generic retry loop with `INTERMITTENT_ATTEMPTS = 6` / `INTERMITTENT_SLEEP = 0.1` defaults matching ferrum. `Browser#with_default_context_wait` is built on top of it for the `NoExecutionContextError` case.
- **CDP error class hierarchy + `BrowserError#code` / `#data` / `JavaScriptError#stack_trace`** — `lib/ferrum/errors.rb` ↔ `lib/capybara/lightpanda/errors.rb`. `NodeNotFoundError`, `NoExecutionContextError`, `JavaScriptError`, `ObsoleteNode`, `DeadBrowserError` all inherit from `BrowserError` (plus compat-only `MouseEventFailed`/`NoSuchPageError`/`StatusError`, never raised — kept so cuprite/ferrum-migrated rescue lists don't NameError), which exposes `response`, `code`, `data`. `JavaScriptError` formats `class_name`, `stack_trace`, and the first 5 frames into the message for log-friendly output.
- **`Cookies` includes `Enumerable`** — `lib/ferrum/cookies.rb` ↔ `lib/capybara/lightpanda/cookies.rb`. `each` yields `Cookie` objects so callers can do `cookies.find`, `cookies.select`, `cookies.to_a` without going through `#all` first. We deliberately keep `#all` returning `Array<Cookie>` rather than ferrum's Hash-by-name shape.
- **`Subscriber` callback isolation** — informal ferrum convention (its `Frame::DOM` callbacks rescue locally to keep the message thread alive) ↔ `lib/capybara/lightpanda/client/subscriber.rb#dispatch`. Per-callback rescue + `on_error:` hook. Critical because `Client#start_message_thread` sets `Thread.current.abort_on_exception = true` — a single raising handler would otherwise tear down the entire CDP connection.
- **`Network#idle?` / `pending_connections` / `wait_for_idle!`** — `lib/ferrum/network.rb` ↔ `lib/capybara/lightpanda/network.rb`. Predicate (`idle?(connections = 0)`), public pending count, and bang-version of `wait_for_idle` that raises `Capybara::Lightpanda::TimeoutError` on timeout. All thin wrappers over the existing `@traffic` array so callers can express idle-as-precondition without a manual `or raise` dance. Refactored `wait_for_idle` to use `idle?` internally for consistency.
- **Promise-aware `evaluate` / `execute` / `evaluate_async` family** — `lib/ferrum/frame/runtime.rb` ↔ `lib/capybara/lightpanda/browser/runtime.rb`. Ferrum's split — raw-expression vs. function-declaration wrapping, plus `awaitPromise: true` for async — is mirrored: `evaluate`/`call_function_on`/`call_with_args` all pass `awaitPromise: true`, and `evaluate_async` wraps the user script in a `Promise` with a `setTimeout` reject so Capybara's `evaluate_async_script` contract works. We deliberately DON'T pass `Node` args through `DOM.resolveNode` (Ferrum's step c) — `serialize_argument` binds them as raw `{objectId:}` instead (simpler; same effect for callFunctionOn).
- **`Downloads` tracker** — `lib/ferrum/downloads.rb` ↔ `lib/capybara/lightpanda/downloads.rb`. `set_behavior(save_path:, behavior:)` → `enable(save_path)` (`Browser.setDownloadBehavior`), `files`, and a blocking `wait`. Lightpanda streams `Content-Disposition: attachment` responses to disk (PR #2722, build ≥7545); we mirror Network's subscribe/reset lifecycle (downloadWillBegin/downloadProgress) and expose `Driver#downloads` / `#wait_for_download`. Our `wait` adds a begin-grace the ferrum version doesn't need (the triggering click's wait_for_idle returns before downloadWillBegin is processed).

### Outstanding adoption candidates

- **[tiny] `Network::Exchange` typed wrapper** — `lib/ferrum/network/exchange.rb` ↔ would replace the loose `{request_id:, url:, method:, response: …}` hashes in our `Network#traffic`. Ferrum exposes `request`, `response`, `finished?`, `blob?`, `loader_id`, `unknown` predicates. Useful when callers want to inspect failed/pending requests; currently they have to peek into the raw hash shape.
- **[medium] Frame-lifecycle idling as a second idle signal** — Ferrum #583, shipped in 0.18.0 (`Frame#lifecycle_events` / `#idle?` / `#loader_id`, fed by `Page.lifecycleEvent`) ↔ our `Network#wait_for_idle` + Turbo sentinels. Lightpanda implements `Page.setLifecycleEventsEnabled` and emits `Page.lifecycleEvent` (incl. child-frame `networkIdle`), so the signal is available to us. Only worth adopting if a real-app spec shows network-traffic counting settling too early or too late; our current two-signal setup has no known gap. Speculative until then.

### Diverged on purpose

- **Console logs are a first-class `Browser#console_logs` buffer, not a user-supplied logger object** — Ferrum's pattern is `options[:logger]` receiving raw CDP traffic, which suites wrap in custom logger classes exposing `.logs`. The gem instead ring-buffers `Runtime.consoleAPICalled` (cap 1,000, Turbo sentinels excluded, cleared on reset) and exposes plain hashes. Simpler for the dominant use case (assert no JS errors); the IO-style `options.logger` stream still exists for raw debugging.
- **`Node#wait_for_stop_moving` does not raise `NodeMovingError`** — Ferrum raises if the element is still moving after `attempts`. Lightpanda has no real animation/rendering loop, so "movement" between samples is just JS style mutation; if it hasn't settled in `MOVING_WAIT_ATTEMPTS` polls, the caller is better off proceeding silently with the last rect than failing the test. Comment in `node.rb` documents this.
- **`Node#click` dispatches synthetic `mousedown`→`mouseup`→`click` `MouseEvent`s from JS, not CDP `Input.dispatchMouseEvent`** — Ferrum dispatches mouse events through CDP and computes content quads (hence its `CoordinatesNotFoundError`). Lightpanda has no real layout, so coordinate-based clicks don't help; `CLICK_JS` in `node.rb` walks down to the element a centered pointer would hit, dispatches the three events, and drives `<a href>` navigation itself via `location.href` (fragment-only targets just set `location.hash`). No `Element.click()` on that path — Lightpanda's click-in-progress flag (#3210) never engages; `IMPLICIT_SUBMIT_JS`/checkbox toggling do call `.click()`, from outside any handler.
- **No `Mouse` / `Keyboard` coordinate abstractions in our public API** — Ferrum exposes `Mouse#scroll_by`, `Mouse#move`, `Keyboard#type` etc. Lightpanda lacks rendering and `window.scrollTo` is a no-op, so most mouse abstractions would be misleading. We have `Browser#keyboard` for `send_keys` only.
- **Returns from CDP serialized via `returnByValue: true`** — Ferrum's `Frame::Runtime#handle_response` walks rich `Runtime.RemoteObject` types (boolean/number/string/undefined/function/object with array/date/null subtypes). We sidestep the whole tree by serializing values upfront, accepting the loss of node references in JS return values in exchange for simpler code paths. Different design, same goal.
- **Node identity is objectId-only — no `DOM.requestNode`/nodeId round-trips** — Ferrum resolves frontend nodeIds per node; their #596 (2026-06-30) had to add `DOM.enable includeWhitespace: "all"` + lazy `requestNode` because whitespace text nodes resolved to nodeId 0 and raised `NodeNotFoundError`. Our nodes bind `{objectId:}` straight into `Runtime.callFunctionOn` (and `DOM.describeNode` takes `objectId:` directly), so that failure class can't occur.
- **No `Frame` class — frame state is `Browser#frame_stack`** — Ferrum models frames as first-class `Frame` objects with `#parent` / `#frame_element` accessors. Our gem keeps `frame_stack` as an `Array<Node>` of `<iframe>` elements; `Driver#switch_to_frame` only needs `:top` / `:parent` / element. The Frame-equivalent accessors are already available as `frame_stack.last` / `frame_stack[-2]` (used in `driver.rb` for `frame_url` / `frame_title`). A `Frame` wrapper would be a speculative abstraction over single-use data.

## Cuprite

Repo: https://github.com/rubycdp/cuprite
Role: peer Capybara CDP driver (built on Ferrum). Lower-priority secondary reference.

**Last reviewed**: 2026-08-28 against Cuprite v0.17 (latest release 2025-05-11) and `main` HEAD `8677fe15` (unmoved since 2026-08-25; open queue still #292 alone) — the July open queue merged in the 08-25 window: #313 empty/nil `send_keys` keys (gem already conforms: `Keyboard#type`'s `case` has no `else`, so `nil` and `""` are no-ops), #315 HTML5 `drag_to` (Adopted below), #316 `Element#drop` (shape comparison under Diverged), #321 `switch_to_window` + `Target.activateTarget` (`8bc64423`) — N/A three ways: fixes Chrome renderer backgrounding (no renderer in Lightpanda), our driver is single-window (`Driver#switch_to_window` raises for any other handle), and `Target.activateTarget` is a stub upstream; #322 `isConnected` guard (Adopted below — ours predates, and atomically); #324 `raise_on_unhandled_modal` (Adopted below); #272 focus-family events construct `FocusEvent` (gem already conforms — `TRIGGER_JS` builds `FocusEvent` for blur/focus/focusin/focusout, predates theirs); #229/#230 color-input `input`+`change` events on `set` (gem immune — a color input falls into `fill_text_input` → `SET_VALUE_JS`, which dispatches both). Ferrum dependency bumped to 0.18. Open queue: only #292 (mobile emulation, stale since 2025-03). Settled, don't re-audit: #317 closed-`<details>` descendants non-visible (Lightpanda's UA sheet does `details:not([open]) > *:not(summary) { display: none }`, so `checkVisibility()` already says no); #318 `tag_name` = `"ShadowRoot"` for `nodeType === 11` (ours predates theirs).

### Adopted

> Pointers below are `file#symbol`, not file:line — line numbers went stale between every sync. Grep the symbol.

- **`Driver#send_keys` fans out to `active_element`** — `lib/capybara/cuprite/driver.rb` ↔ `lib/capybara/lightpanda/driver.rb#send_keys`. Capybara's `Session#send_keys` routes to `Driver#send_keys`; Cuprite's pattern is to forward to whatever element currently has focus. Our copy notes "Cuprite's pattern".
- **Expanded `invalid_element_errors` list** — `lib/capybara/cuprite/driver.rb` ↔ `lib/capybara/lightpanda/driver.rb`. Cuprite includes 5 errors; our copy lists only the 3 we can raise (`NodeNotFoundError`, `NoExecutionContextError`, `ObsoleteNode`). `MouseEventFailed` / `CoordinatesNotFoundError` dropped — gem dispatches clicks through JS, no coordinate-based mouse path exists.
- **`native_args` private helper** — `lib/capybara/cuprite/driver.rb` ↔ `lib/capybara/lightpanda/driver.rb#native_args`. Walks args before sending to the browser and unwraps `Capybara::Node::Element` to its `.base`.
- **Smart `Node#[]` property/attribute resolver** — `lib/capybara/cuprite/node.rb#[]` ↔ `lib/capybara/lightpanda/node.rb#[]` + `PROPERTY_OR_ATTRIBUTE_JS`. Returns resolved URLs for `src`/`href`/`action` and live property values for boolean attributes (checked/selected/etc.).
- **Whitespace-normalized `filter_text`** — `lib/capybara/cuprite/node.rb#all_text` ↔ `lib/capybara/lightpanda/node.rb#filter_text`. Strips control chars, collapses whitespace, trims, normalizes NBSP. Required because Lightpanda's `textContent` preserves source-template whitespace differently than Chrome.
- **`Node#rect`** — Cuprite PR #276 ↔ `lib/capybara/lightpanda/node.rb#rect` + `GET_RECT_JS`. Exposes `getBoundingClientRect` (synthetic geometry — see `lightpanda-io.md` limitation #2).
- **`Node#obscured?`** — Cuprite PR #291 ↔ `lib/capybara/lightpanda/node.rb#obscured?` + `_lightpanda.isObscured`. Hit-tests `elementFromPoint` at the element's center.
- **`Node#shadow_root`** — Cuprite PR #234 ↔ `lib/capybara/lightpanda/node.rb#shadow_root`. Returns a `Node` wrapper for the element's `shadowRoot`. Our `Node#tag_name` also reports `"ShadowRoot"` for `nodeType === 11`, which Cuprite only added later (#318).
- **Time-input support in `Node#set`** — Cuprite PR #245 (merged 2026-03-28) ↔ `lib/capybara/lightpanda/node.rb#fill_input` (date / time / datetime-local / month / week cases). Month uses `strftime("%Y-%m")`; week uses ISO 8601 `strftime("%G-W%V")` so the last days of December that belong to ISO week 1 of the next year still render with the correct year — matches Cuprite's choice and what the user types into `<input type=week>`.
- **`Node#parents`** — `lib/capybara/cuprite/node.rb#parents` ↔ `lib/capybara/lightpanda/node.rb#parents` + `Browser#parents_of` + `PARENTS_JS` in `browser/finder.rb`. Walks `parentNode` from `this` up to (but excluding) `ownerDocument`, returns the chain as Lightpanda::Node wrappers.
- **Focus-before-value-set** — Cuprite PR #280 ↔ our `SET_VALUE_JS` (which calls `this.focus()` before `this.value = value`).
- **`Driver#default_domain` + `started` flag** — `lib/capybara/cuprite/driver.rb` ↔ `lib/capybara/lightpanda/driver.rb#default_domain`. `set_cookie` falls back to the host of `browser.current_url`, then `Capybara.app_host`, then `"127.0.0.1"`, gated by an internal `@started` flag flipped on first `visit`. Lets pre-visit cookie setup work without CDP `InvalidParams`.
- **`Node#trigger(event)`** — `lib/capybara/cuprite/node.rb#trigger` ↔ `lib/capybara/lightpanda/node.rb#trigger` + `TRIGGER_JS`. Fires an arbitrary DOM event by name (mouse/focus/form pick the right Event constructor; everything else goes through generic `Event` so custom names like `lp:custom` still dispatch).
- **Invalid selector → `InvalidSelector`** — `lib/capybara/cuprite/javascripts/index.js#find` ↔ `lib/capybara/lightpanda/browser/finder.rb` (`FIND_WITHIN_JS`, `FIND_IN_FRAME_JS`, `find_in_document`). Throws from `querySelectorAll` rewrap with `LIGHTPANDA_INVALID_SELECTOR:` marker → `Capybara::Lightpanda::InvalidSelector`. Cuprite checks `DOMException.SYNTAX_ERR`; we catch unconditionally because Lightpanda's V8 throws generic `Error` not DOMException — safe because the only `querySelectorAll` failure mode is selector parsing.
- **`raise_on_unhandled_modal`** — Cuprite #324 (merged 2026-08-25, superseding draft #320) ↔ `options.rb` + `browser/modals.rb#check_unhandled_modal!`. Merged shape converged on ours: same option name, warn-by-default, always auto-accepts, dedicated `UnhandledModalError`, deferred raise — theirs stashes the error in the dialog handler and a `Page#command` override raises it on the next CDP round-trip (same can't-raise-on-the-dispatcher-thread constraint we hit); ours surfaces from `Browser#wait_for_idle`/`#go_to`. Equivalent placement, nothing to change. Pre-arm bookkeeping (`@modal_armed`) is single-shot to match Lightpanda's own `LP.handleJavaScriptDialog` slot. Subscription now installed from `create_page`, not lazily on the first accept.
- **`isConnected` guard → `ObsoleteNode` on every node operation** — Cuprite #322 (`node.rb#command` pre-checks `this.isConnected` with a separate `evaluate`) ↔ `lib/capybara/lightpanda/node.rb#call` + `wrap_with_attached_guard`. Ours folds the check into the same `Runtime.callFunctionOn` as the operation (one round-trip, no gap between check and use) and maps the marker to `ObsoleteNode`, which `Driver#invalid_element_errors` hands to Capybara's `automatic_reload`. Predates theirs.
- **HTML5 `Node#drag_to`** — Cuprite #315 (`javascripts/drag.js`, merged 2026-08-20) ↔ `lib/capybara/lightpanda/node.rb#drag_to` + `HTML5_DRAG_JS`/`LEGACY_DRAG_CHECK_JS` (adopted 2026-08-24). Both port Capybara's Selenium `HTML5_DRAG_DROP_SCRIPT` near-verbatim (pure `DragEvent` simulation via `evaluate_async`, no CDP `Input`); 12/13 `#drag_to HTML5` shared specs pass on nightly ≥8796 (sole skip: SortableJS's mouse path; the fractional-clientX skip fell with upstream #3259). Two deviations from Cuprite: their `legacyDragCheck` falls back to coordinate mouse dragging, ours raises `NotImplementedError` (no mouse); raw `.draggable` reads are native — upstream shipped the IDL in #3257 (≥8793) and the polyfill was retired with the 8796 floor bump (2026-08-25). Tested by `test/features/drag_test.rb` + the shared battery.

### Outstanding adoption candidates

- **[tiny] `setValue` uses native HTMLInputElement value setter** — `lib/capybara/cuprite/javascripts/index.js#setValue` ↔ our `SET_VALUE_JS`. Cuprite calls `Object.getOwnPropertyDescriptor(window.HTMLInputElement.prototype, "value").set` to bypass framework value setters (React-style). Lightpanda's React SSR/hydration support is limited so this is mostly latent; defer until we have a test that needs it.
### Diverged on purpose

- **`Node#set` writes `.value` directly + dispatches input/change** — Cuprite types char-by-char and dispatches `keydown` / `keypress` / `input` / `keyup` per character (`lib/capybara/cuprite/javascripts/index.js#set`). Lightpanda's keyboard event handling is limited and per-char CDP dispatch is much slower and more error-prone; direct `.value` + `input`/`change` events is the right choice for the gem's perf and stability. Tests that assert keystroke-level handlers may need to use `node.send_keys` instead of `node.set`.
- **`Node#click` is synthetic JS event dispatch (`CLICK_JS`), not `Input.dispatchMouseEvent`** — Cuprite uses content-quad coordinates (hence its `mouseEventTest` JS helper and `CoordinatesNotFoundError`). Lightpanda has no rendering or coordinate system; see the matching Ferrum divergence for what `CLICK_JS` does instead.
- **`isObscured` is single-frame** — Cuprite's `isObscured` walks up `frameElement` chain and accumulates offsets to support obscuring detection across nested iframes (`lib/capybara/cuprite/javascripts/index.js#isObscured`). Our `_lightpanda.isObscured` only inspects the current document. Could be added but rarely needed in tests.
- **`isVisible` delegates to native `checkVisibility()` instead of walking parents in JS** — Cuprite walks ancestors itself, reading `display`/`visibility`/`opacity` off `getComputedStyle` at each level (and, since #317, special-casing closed `<details>`). Our `_lightpanda.isVisible` is a 5-line wrapper: reject `visibility: hidden|collapse` (which `checkVisibility`'s spec defaults ignore), then return `el.checkVisibility()`. That single native call already accounts for inline styles, author stylesheets incl. `@layer` (#2719), external `<link>` sheets, and the whole UA sheet (`[hidden]`, `input[type=hidden]`, closed-`<details>` children). A JS cascade walk would be strictly less accurate here, since Lightpanda's `getComputedStyle` does *not* resolve arbitrary properties from stylesheets. One real behavioral difference: Cuprite also rejects `opacity: 0`, we don't (`checkVisibility`'s `opacityProperty` defaults to false per spec). Untested by the Capybara battery — its only `opacity` reference is `attach_file`'s `make_visible:` helper — so it has never surfaced as a failure. Add an explicit opacity check only if a real app needs it.
- **`visible_text` is a thin gate over native `innerText`, not a full walker** — Cuprite still ships a full JS `visibleText` walker; we lean on native `Element.innerText`, which does spec-compliant rendered-text collection (block line breaks, `display:none` descendant skipping, whitespace) since Lightpanda #2785/#2795 (build ≥7571, in the floor). `_lightpanda.visibleText` is therefore ~14 lines: gate on `isVisible` (a non-rendered element must read `""` — innerText's getter step 1 returns `textContent` instead), plus a `ShadowRoot`/`DocumentFragment` branch (fragments have no `innerText`) concatenating visible children's innerText with whitespace-collapsed text nodes. Block-break fidelity is the browser's, which beats the tag heuristic it replaced.
- **`window._lightpanda` namespace, not `window._cuprite`** — Cuprite's JS bundle exposes `window._cuprite`; we use `window._lightpanda`, registered once via `Page.addScriptToEvaluateOnNewDocument` rather than per-frame injection. The bundle is small and split by concern under `javascripts/`: `turbo.js` (Turbo activity tracking) + `predicates.js` (`isVisible`/`isObscured`/`isDisabled`/`isContentEditable`/`visibleText`), wired by `attach.js`, assembled into one IIFE by the `AutoScripts` linker (`auto_scripts.rb`). The source files carry no module syntax so the Bun harness (`test/js/`) can load `predicates.js` via `new Function(...)` and unit-test the predicate logic with no build step. The XPath 1.0 evaluator that used to live here moved to native `Document.evaluate` in `browser.rb` (PR #2305); the `#id` rewriter was retired; and `form.requestSubmit()` is a direct call in `node.rb`'s click pipeline, not a polyfill.
- **Drag-and-drop: gem ships `Node#drop` + HTML5 `drag_to`; coordinate paths stay out** — Capybara's `Element#drop` lives in `node.rb` (`DROP_JS` + `attach_drop_input`): files go through a hidden `<input type=file>` + `DOM.setFileInputFiles` (adopted 2026-08-18, replacing base64-over-CDP and its ~70 MB ceiling), `{mime => data}` hashes become typed items, then `dragenter`→`dragover`→`drop` fire. Needs Lightpanda `DataTransfer`/`DragEvent` (#2671, ≥6699). Cuprite's #316 (merged 2026-08-20) uses the same transport but appends its input to `document.body` and fires only `drop`; ours attaches in the dropzone's own document (iframe-safe) and fires the full event sequence (dropzones often gate on `dragover` preventDefault) — keep ours. `drag_to`'s HTML5 half is Adopted (see above); coordinate `drag_by` and the legacy-mouse half of `drag_to` remain out (no layout — `NotImplementedError`). Tested by `test/features/drop_test.rb` + `drag_test.rb`.
