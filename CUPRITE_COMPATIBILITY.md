# Migrating Cuprite and Selenium suites to Lightpanda

The first migration round landed on `main` at `bb8303a`. An application can keep its driver name and use the registration, header, cookie, network and download helpers below. The comparison targets Cuprite 0.20.1, Ferrum 0.20.1 and Capybara 3.40.0. Cuprite deprecates several driver-level helpers in favor of their browser-level equivalents. [Cuprite deprecations](https://github.com/rubycdp/cuprite/blob/v0.20.1/CHANGELOG.md)

## Selenium migration evidence

Decidim uses `page.driver.browser.manage.cookie_named(name)` to check a consent cookie’s expiry, domain, SameSite, HttpOnly and secure flags. Its sign-out helpers also use `all_cookies` and `delete_all_cookies`. At gem commit `9f9ba4d`, these calls raised `NoMethodError` at `manage`. They now operate on cookies visible to the current document, including HttpOnly cookies. A cookie confined to another path or host survives deletion, including a parent host’s private cookie with the same name and path. When multiple visible cookies share a name, select by domain and path from `all_cookies` for a deterministic result. On IPv6 loopback Lightpanda preserves the domain `[::1]`; Selenium 4.41.0 truncates it to `[` when converting the cookie. When a named cookie is missing, the adapter raises Selenium’s `NoSuchCookieError` if Selenium is loaded, otherwise `Capybara::Lightpanda::NoSuchCookieError`. [Original consent specs](https://github.com/decidim/decidim/blob/d22e3584e07045fea4f1c759454cbfd5478168e7/decidim-core/spec/system/data_consent/organization_spec.rb) · [Differential contract](test/compatibility/selenium_contract.rb)

All seven HTTP examples in that file passed unchanged on Selenium WebDriver 4.41.0 with Chrome 156.0.8078.4 and on Lightpanda 1.0.4. For the Lightpanda run we added the gem and changed the body of the `:headless_chrome` registration. The original CDP setup hook, teardown and spec assertions ran on both. The local harness supplied the browser executables, an isolated database and a fixed server port. The PWA, mobile and HTTPS modes were outside this run. Run the cookie contract with `bundle exec ruby test/compatibility/selenium_contract.rb` and repeat with `CONTRACT_DRIVER=selenium`.

Decidim’s `expect_no_js_errors` helper checks every entry returned by `page.driver.browser.logs.get(:browser)` for a `SEVERE` level. That view now includes uncaught exceptions and unhandled promise rejections alongside console errors. The native `console_logs` and `page_errors` APIs still provide separate sources. Repeated reads on Lightpanda retain entries until session reset or explicit clearing of the corresponding source. Chrome drains its browser log on read. Lightpanda uses coarse browser-clock timestamps. Chrome reports Unix milliseconds. Entries sharing a Lightpanda timestamp can appear in a different order. [Decidim helper](https://github.com/decidim/decidim/blob/d22e3584e07045fea4f1c759454cbfd5478168e7/decidim-dev/lib/decidim/dev/test/rspec_support/frontend.rb)

The original account example “does not have js errors” passed unchanged on both engines with Decidim’s original console teardown. The shared contract also injects failures so it would catch a false pass when an uncaught error goes missing. The real-app fixture now preserves the teardown as written. [Account example](https://github.com/decidim/decidim/blob/d22e3584e07045fea4f1c759454cbfd5478168e7/decidim-core/spec/system/account_spec.rb) · [Differential contract](test/compatibility/selenium_contract.rb)

Decidim’s comments helper resizes to 375×667 before visiting a mobile view and restores 1920×1080 with `page.driver.browser.manage.window.resize_to(width, height)`. The original “shows kebab menu functionality” example in the debates suite passed unchanged on Selenium/Chrome and Lightpanda. It opens the comment menu and checks its visibility. The adapter returns a WebDriver-shaped rectangle for the single virtual window, with origin (0, 0). Integer-like dimensions follow Selenium’s Ruby conversion. Lightpanda cannot represent a zero-sized viewport and raises `Capybara::NotSupportedByDriverError` for that request. [Decidim comments helpers](https://github.com/decidim/decidim/blob/d22e3584e07045fea4f1c759454cbfd5478168e7/decidim-core/lib/decidim/core/test/shared_examples/comments_examples.rb) · [Debates system spec](https://github.com/decidim/decidim/blob/d22e3584e07045fea4f1c759454cbfd5478168e7/decidim-debates/spec/system/comments_spec.rb)

Set the viewport at the start of each responsive example, before visiting. Lightpanda restores its configured dimensions on session reset. Selenium/Chrome retains the resized window. JavaScript sees the new viewport immediately. Lightpanda evaluates stylesheet media rules when parsing a document and has synthetic element geometry. Keep a Chrome lane for live reflow, window positioning and rendered pixel assertions. [Viewport implementation](lib/capybara/lightpanda/browser.rb) · [Differential contract](test/compatibility/selenium_contract.rb)

Decidim’s download hook sets `page.driver.browser.download_path = DownloadHelper::PATH.to_s` before each export. Its original open-data spec passed on Selenium/Chrome and Lightpanda, opening the downloaded ZIP and checking all seven expected CSV entries. Use an absolute path on the browser host. Reading the ZIP from a remote runner requires a shared directory. The browser creates the directory when the download begins. Lightpanda and Chrome Headless Shell 156 restored the configured destination on reset. Full Chrome 156 in headless mode retained the last override. Set the path in each example, as Decidim does. If a destination change times out, set it again before inspecting Lightpanda’s file list. The differential contract switches destinations twice and reads the bytes from disk. [Download hook](https://github.com/decidim/decidim/blob/d22e3584e07045fea4f1c759454cbfd5478168e7/decidim-dev/lib/decidim/dev/test/rspec_support/z_download_helper.rb) · [Open-data system spec](https://github.com/decidim/decidim/blob/d22e3584e07045fea4f1c759454cbfd5478168e7/decidim-core/spec/system/download_open_data_files_spec.rb)

Decidim reads `page.find(selector).native.attribute("validationMessage")` after an invalid submission. The original initiative example for a missing scope passed with its original English validation message on Selenium/Chrome and Lightpanda. The shared helper also checks an empty input, then fills both controls and verifies that the validation messages clear. The native Selenium spelling reads live primitive properties as strings and falls back to markup for custom attributes. Capybara’s `element[name]` retains its own contract. Message wording depends on the browser and locale. The comparison uses Capybara 3.40’s default Selenium attribute reader. Its string value for an enabled field’s `disabled` property is `"false"`. [Decidim validation helper](https://github.com/decidim/decidim/blob/d22e3584e07045fea4f1c759454cbfd5478168e7/decidim-dev/lib/decidim/dev/test/rspec_support/forms_validations.rb) · [Initiative spec](https://github.com/decidim/decidim/blob/d22e3584e07045fea4f1c759454cbfd5478168e7/decidim-initiatives/spec/system/create_initiative_spec.rb) · [Capybara’s Selenium attribute reader](https://github.com/teamcapybara/capybara/blob/3.40.0/lib/capybara/selenium/atoms/src/getAttribute.js)

## Forem migration evidence

Forem’s JavaScript system specs select `:better_cuprite` in a shared RSpec hook. To migrate its local headless run, replace the test gem and the registration in `spec/support/initializers/cuprite.rb`. Keep the existing driver name, viewport, timeouts, headless check, empty `browser_options: {}` and `pending_connection_errors: false`. The shared hook and the application specs can stay as written. The adapter still rejects custom Chrome flags and a request to raise Cuprite pending-connection errors. A refused Capybara `visit` raises a status error on both opt-in drivers. Lightpanda raises `Ferrum::StatusError` when Ferrum is loaded and `Capybara::Lightpanda::StatusError` otherwise. HTTP responses such as 404 remain available for assertions, and a slow subresource can still finish after the visit returns. Native Lightpanda sessions and direct calls to `page.driver.browser.goto` can inspect the browser’s error document. Use Capybara’s `visit` when a migrated helper expects a refused connection to raise. The [differential contract](test/compatibility/cuprite_contract.rb) holds a page script open past the navigation timeout, then releases it and checks that the script runs. [Forem initializer](https://github.com/forem/forem/blob/3a22391a6d83ee1fda6a185799c86dcb76800318/spec/support/initializers/cuprite.rb) · [Integration patch](.github/real-apps/patches/forem.patch)

Two original Forem examples passed on Cuprite 0.15 with Chrome 156.0.8078.4 and on Lightpanda 1.0.4. “Creates a new user” submits the sign-up form and checks the database. “Doesn't display blocked articles” checks that the blocked author's card is hidden. Both comparison runs used the same prebuilt assets and original assertions. The CI fixture retains its existing feed assertion because Forem can also omit the article server-side. [Sign-up example](https://github.com/forem/forem/blob/3a22391a6d83ee1fda6a185799c86dcb76800318/spec/system/authentication/user_logs_in_with_email_spec.rb) · [Blocked-article example](https://github.com/forem/forem/blob/3a22391a6d83ee1fda6a185799c86dcb76800318/spec/system/articles/feeds/basic_spec.rb) · [CI fixture rationale](https://github.com/navidemad/capybara-lightpanda/pull/201)

Remove the Chrome inspector option for the Lightpanda registration. Keep a Chrome registration for interactive inspection and headed runs. For remote runs set Forem’s existing `CHROME_URL` variable to the Lightpanda `ws://` endpoint. The fixture passes that value as `ws_url:` and rejects a copied Chrome HTTP discovery URL before launch. The original pinned Cuprite 0.15/Ferrum 0.14 bundle and this gem require incompatible versions of `websocket-driver`, so the comparison used separate bundles. The Cuprite 0.20.1 contract covers coexistence in one bundle. [Cuprite 0.15 inspector](https://github.com/rubycdp/cuprite/blob/v0.15/lib/capybara/cuprite/driver.rb) · [Registration options](lib/capybara/lightpanda/cuprite_driver.rb)

As an additional three-driver check, the same original Forem blocked-article example also passed with Selenium 4.41.0 and Chrome in the same local app fixture. That supplemental registration needed Capybara 3.40.0 because Forem’s pinned 3.37.1 logger integration failed to initialize Selenium 4.41.0. The sign-up example on that supplemental combination failed its user-count assertion. The Cuprite-to-Lightpanda migration results above use Forem’s own Capybara constraint.

## Which suites still need Chrome?

- **URL policies and HTTP auth (larger).** Cuprite 0.20.1 accepts constructor keys `url_blacklist:` / `url_whitelist:` and browser setters under both old and new names. The modern **constructor** spellings are on upstream main and absent from the release. Lightpanda currently consumes none of them. Its native block command has a different pattern language and survives context disposal. Start with a documented pattern subset, reject unrepresentable expressions, and verify allowed and denied requests against a local server. Test two sessions and a reset, including restoration of configured policy. Arbitrary Ruby regexes, interception callbacks and challenge-based `network.authorize` warrant a separate Fetch-domain implementation and tests. [Cuprite browser](https://github.com/rubycdp/cuprite/blob/v0.20.1/lib/capybara/cuprite/browser.rb) · [Constructor change](https://github.com/rubycdp/cuprite/pull/361) · [Lightpanda protocol inventory](.claude/rules/lightpanda-io.md)
- **Raw Ferrum helpers.** Search the adopting suite for `page.driver.browser.page`, `on(:request)`, `console`, `at_css`, `native.node` and rescues naming `Ferrum::` or `Capybara::Cuprite::`. Lightpanda has its own browser, node handles, event payloads and exception classes. A shared method name such as `command` does not establish the same target or return type. Port the specific helper to Capybara or a narrow adapter. Preserve Capybara’s stale-node retry behavior and distinguish JS, selector and transport errors. [Ferrum browser](https://github.com/rubycdp/ferrum/blob/v0.20.1/lib/ferrum/browser.rb) · [Lightpanda errors](lib/capybara/lightpanda/errors.rb) · [Event dispatch](lib/capybara/lightpanda/client/subscriber.rb)
- **Keep a Chrome lane for rendering and multi-window flows.** Lightpanda supports one window, synthetic geometry and a JS-visible viewport. Its scroll helpers are no-ops. A screenshot call can succeed without generating useful visual evidence. Keep actual scrolling, coordinates, CSS hover, image/PDF assertions, multiple tabs, and opener relationships on Cuprite. DOM hover events, HTML5 drag/drop, file upload, iframe scripting and explicitly handled dialogs already have Lightpanda paths. Downloads need their own fixture for an attachment or a download link. A MIME-only navigation has different behavior. [Shared-spec capability list](spec/features/session_spec.rb) · [Specific skipped behaviors](spec/spec_helper.rb) · [Download fixtures](test/features/download_test.rb)
